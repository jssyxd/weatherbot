# weatherbot — tree11-yes

> **研究与纸面验证边界。** 本分支只生成、回放和审计纸面信号/订单意图。它不加载钱包或私钥，不创建 CLOB 认证头，不提交、取消或卖出真实订单。任何真实执行、持仓对账与订单取消均不在本分支的实现范围内。

**tree11-yes** 基于最新 `tree5` 创建。它研究的不是 tree1–4 的“已死桶 BUY NO”，而是另一类可验证假说：当新到达的 METAR/SPECI/COR 首次将某一**独立的高温或低温合同**中、`t0` 前市场仍广泛相信的旧 TAF 预测温度桶事实证伪时，系统是否能在当前日内极值所在的**新桶**生成有价值的 `paper BUY YES` 候选。

这不是“确定能抢到单”或“确定盈利”的承诺。所有速度、价格和成交判断都必须以时间戳、完整 L2 深度、费用、部分成交与最终结算的前瞻性记录验证。

## tree5 继承的功能

| 能力 | tree5 的实现与边界 | tree11-yes 的处理 |
|---|---|---|
| 实况气象 | CheckWX `METAR/SPECI short` 主源，每 120 秒扫描；主源失败或缺报时仅对缺口机场以 AviationWeather.gov 已发布报文回退。 | 原样继承。每条新报文的原文、`observed`、`fetched_at`、来源和端点必须保留。 |
| 日内极值 | 以机场 IANA 时区归属当地自然日；暖机不完整时失败关闭。 | 原样继承；只有可信的 running high/running low 可以参与事实逆转。 |
| TAF | 每个城市本地 01:00 后抓取 TAF，解析 `TX`/`TN` 极值组并映射温度桶。 | 要归档所有版本；比较基准只能是 `t0` 前程序**实际可见的最近一版 TAF**。 |
| 市场规则 | Gamma 元数据分离最高/最低温事件，解析 C/F 区间与 YES/NO token。 | 原样继承，并选择当前观测极值唯一落入的目标 YES 桶。 |
| 订单生命周期 | tree5 对已有 TAF YES 入场保留证伪、取消和退出意图；真实执行被刻意阻断。 | 本阶段只记录新 YES 的纸面 intent。新持仓被再次证伪后的取消、退出和下一桶重开将独立开发。 |

## 独立市场、事实逆转与温度桶

高温和低温是不同预测市场，**必须独立运行**；高温信号不能与低温信号合并，任何一边达到条件即可创建自己的候选。设 `t0` 为程序收到新报文的单调时钟时间，`T_old` 是 `t0` 前已保存且覆盖本地合约日的最近可见 TAF，`B_old` 是其 `TX` 或 `TN` 温度所处的唯一合同桶，`E(t0)` 是截至报告 `observed` 时刻的日内极值。

| 方向 | 旧桶已被事实证伪的必要条件 | 新 YES 候选的目标桶 |
|---|---|---|
| 当日最高温 | `running_high >= B_old.hi` | 包含 `running_high` 的唯一高温市场桶。 |
| 当日最低温 | `running_low < B_old.lo` | 包含 `running_low` 的唯一低温市场桶。 |

这使用**合同区间边界**，而不是“只比 TAF 点预测高/低一度”。C 合同常以 1°C 区间定义，F 合同常以 2°F 范围定义；程序只信任 Gamma 规则快照中的半开区间 `[lo, hi)`。若实际温度只变一格但仍在同一个 F 桶，或当前极值不能唯一映射某桶，均须跳过。若一次跳过多个桶，只能选择当前极值真正落入的桶，不得臆造相邻桶。

所有条件须同时满足：

1. 报文 `fetched_at - observed` 严格小于 300 秒；缺失、负龄期或未来时间均失败关闭。
2. `T_old` 的 `issued/fetched` 记录均不晚于 `t0`，并且它的 TX/TN 覆盖相同城市、方向和本地合约日。
3. 旧桶在 `t0` 前被上表的日内极值穿越；新桶与旧桶不同。
4. 旧桶在 `t0` 前通过下述联合共识门；新桶在信号时刻有 fresh L2、tick、最小数量和限价内可见 ask 深度。

若 `t0` 前最新可见 TAF 已经移动到新桶或其他非旧桶，则跳过。这样可防止把公开 TAF 更新后的重定价错写成 METAR 时效优势。

## 价格 + 可执行 L2 深度联合共识门

固定“过去 120 分钟”不等于市场共识。tree11 采用**可配置 120 分钟最大窗口 + 数据覆盖 + 价格排名 + 深度支持 + 最近性**。以下默认值是待前瞻样本检验的预注册研究参数，不能直接理解为真实交易指令。

| 条件 | 默认研究口径 | 目的 |
|---|---|---|
| 时间隔离 | 只读 `[t0-120min, t0)` 的录制市场快照。 | 防止以后验价格解释事前共识。 |
| 覆盖与最近性 | 至少 45 个有效快照，最后有效快照距 `t0` 不超过 4 分钟。 | 避免把稀疏、断线或陈旧行情称为共识。 |
| 价格主导 | 旧桶的时间加权**可执行 bid**中位数，在同一方向/城市/日期市场所有桶中排名第一；相对第二名须有预配置的最小价差。 | 不以单笔 last trade、单次高价或不可成交 midpoint 判定。 |
| 深度主导 | 旧桶在有效快照上达到预配置的 L2 可执行 bid 金额和目标股数倍数门槛。 | 排除“显示高价但一碰就没深度”的伪共识。 |
| 新桶可买 | 新桶 best ask、tick、min order size 均完整，且限价内累计 ask 深度达到目标数量。 | 区分发现方向与可纸面成交。 |

窗口不是必须固定 120 分钟：实验应并列 30、60、120、180 分钟，并进行按日期的 walk-forward 对比。每个窗口还必须报告有效覆盖、最长断线、旧 TAF 版本龄期与事件到达时延；少于最小覆盖的窗口直接 `BLOCKED`，不得通过减少窗口“补足样本”。

## 速度与价格研究方法

软件无法确保赢得公开信息发布后的竞争。tree11 将在同一冻结信号上并列记录**预注册**的纸面执行假设，如 `best_ask`、`best_ask + 1 tick`、受最高价保护约束的有限追价，以及不同 FAK/GTC 生命周期。每种假设均使用同一时刻的完整 L2、费用、最小数量、部分成交、订单 TTL 和延迟模型计算；无深度、非 tick 对齐、价格超保护上限、数据陈旧或规则缺失时一律 `BLOCKED`。

因此首要产出不是提高下单次数，而是回答：候选在报文到达前是否有真实旧桶共识、新桶是否可买、在明确价格保护下有多少可见深度、以及后续是否仍被新的事实推翻。

## 未来的持仓管理（未实现）

若已对账的纸面或真实 `B_new` YES 持仓后来被新的 METAR/SPECI/COR 证伪，未来模块必须顺序完成：停止新入场、取消未成交买单、确认已成交数量、生成退出意图。重新进入另一个温度桶必须是新的独立 `signal_id`，重新进行 TAF 可见性和共识检查；不能把“平旧仓”和“开新仓”假设为同一原子成功操作。
