# tree6yes：尾盘共识 YES 策略设计

## 范围与安全边界

本设计仅适用于 `tree6yes` 分支，并保留仓库现有的失败关闭边界：策略只生成审计记录和纸面成交估算，不读取钱包、不加载私钥、不签名，也不提交、撤销或修改任何真实订单。所有进入、卖出和换手均以 `paper` 结果表示；`live` 模式一律返回阻断记录。

本分支完全移除“死桶击杀后买 NO”的入场路径。市场规则须同时保存每个温度桶的 `yes_token_id` 与 `no_token_id`，但策略只会订阅和使用 `yes_token_id`；任何缺失 YES token 的候选都失败关闭。方案 A 已确认：保留公共盘口推送，且已成交持仓的 YES 最优 bid 跌破 85¢ 时仅立即预警和审计，绝不在缺乏实测温度证据时卖出、开新仓或换手。

## 数据节奏与延迟事实

| 数据面 | 更新方式 | tree6yes 规则 | 目的 |
| --- | --- | --- | --- |
| CheckWX METAR/SPECI | HTTP 拉取 | 每 900 秒一次 | 降低天气 API 请求频率，重建当天极值并在下一轮确认实际温度越界。 |
| Gamma 市场结构 | HTTP 拉取 | 每 900 秒一次且本地日切换时强制刷新 | 更新可交易城市、方向、温度桶及 YES token 映射。 |
| Polymarket CLOB 市场数据 | 公共 WebSocket 推送，不轮询 | 常驻订阅已发现的 YES tokens，心跳 10 秒 | 使用可执行 bid/ask 与完整盘口深度进行入场、卖出和风控。 |

> 15 分钟的天气拉取与“发现实测温度突破后立即退出”不能同时成立。没有天气推送源时，实测温度越界的确认延迟最多接近一个扫描周期；盘口变动可通过公共市场数据流近实时触发风控，但它是市场信号，不等同于实测温度确认。[1]

Polymarket 显示价格并不必然是成交价格；买入必须以 YES 的最优 ask 和可用 ask 深度判定，卖出必须以 YES 的最优 bid 和可用 bid 深度判定。[2]

## 尾盘共识 YES 入场规则

每个候选的唯一键为 `city_id | market_local_date | direction`。同一个键当日最多建立一个初始持仓；不同城市和高温/低温方向可以并行存在，从而实现分散化，但受全局持仓上限约束。

| 规则 | 默认配置 | 判定 |
| --- | ---: | --- |
| 高温尾盘时段 | 12:00–17:00 当地时间 | 仅在城市 IANA 时区的该区间内考虑高温合约。 |
| 低温尾盘时段 | 01:00–05:00 当地时间 | 仅在城市 IANA 时区的该区间内考虑低温合约。 |
| 连续稳定门 | 30 分钟 | 同一城市、日期、方向和同一 YES token 的可执行共识价格必须持续不低于 0.90；价格跌破、缺失或 token 改变即重新计时。 |
| 入场 ask 区间 | 0.92–0.98，含端点 | 只在 YES 最优 ask 落在该区间、盘口新鲜、且从 ask 侧累计深度满足目标股数时生成候选。 |
| 限价方式 | `best_ask_plus_one_tick` | 默认按 `min(best_ask + tick_size, 0.98)` 提交纸面 FAK 限价；若该价格不能提供足额成交，则失败关闭。设为 `best_ask` 可关闭加一跳行为。 |
| 初始股数 | 5 | 与仓库既有最小订单规模假设一致，按多城市机会分散，而不是在同一机会加码。 |
| 最大同时持仓 | 10 | 达到上限后不新增候选，以避免策略把多个相关天气市场误当独立风险。 |

“共识”按**可执行 YES 盘口**定义，而非 Gamma 显示价格或 midpoint：在全部同方向桶中，只有一个 YES token 同时满足稳定门、价格区间和深度门时才可入场；若多个温度桶合格，则拒绝，原因是市场对最终温度并未形成单一可交易共识。

## 持仓保护与一次换手规则

持仓保存入场 token、买入均价、持股数、城市/日期/方向、初始温度区间、首次入场时间，以及 `rotation_count`。策略不买 NO，也不会通过持有 NO 进行对冲。

| 触发器 | 证据门 | 纸面动作 | 失败关闭处理 |
| --- | --- | --- | --- |
| 实测温度突破当前 YES 桶上/下界 | 下一次 CheckWX 扫描得到新极值，且报文新鲜、F 单位精度足够、当日暖机完成 | 以当前 YES 最优 bid 估算卖出全部旧仓位；若另一单一 YES 共识桶通过入场门，则估算买入旧仓位 3 倍股数的替代仓位。 | 缺乏可卖 bid/深度时不伪造退出；记录 `exit_unavailable`。新桶不合格时仅尝试退出，不重新入场。 |
| 市场先行反转 | 已成交持仓的 YES 最优 bid 跌破 `0.85`；或同方向出现另一单一合格 YES 共识桶 | 立即生成 `market_reversal_alert`，但不卖出、不开新仓，也不换手。 | 此行为已由用户确认；只有后续 CheckWX 新鲜实测温度证据表明当前持仓桶失效时，才可触发纸面卖出和一次 3 倍 YES 换手。 |
| 一次换手已执行后再次反转 | `rotation_count >= 1` | 不再追单或二次加码，最多尝试按 bid 退出。 | 记录 `rotation_limit_reached`。 |

换手的“3 倍”是**新 YES token 的买入股数**，不是旧仓位继续加仓：假设初始持有 5 股，则先估算卖出旧 token 的 5 股，再估算买入替代 token 的 15 股。纸面账本把卖出回收金额、买入成本、滑点与净现金变化分列，绝不将卖出价格误当作买入价格。

## 状态与审计

状态文件新增 `tail_consensus`（每个候选的连续稳定起点和最近价格）及 `tail_positions`（已进入的纸面持仓）。每一次行情更新、入场拒绝、入场估算、温度越界、卖出估算、换手估算以及失败关闭结果都写入信号 JSONL 与 SQLite 审计账本。

## 验收测试

测试至少覆盖：900 秒配置与低于 900 秒拒绝；市场规则解析出 YES token；高温与低温本地尾盘窗口；30 分钟稳定门重置；0.92、0.98 边界及超过 0.98 拒绝；盘口加一跳不越过 0.98；只有一个可交易 YES 共识桶；缺 ask/bid、过期本地簿和深度不足时失败关闭；只生成 BUY_YES 与 SELL_YES；实测越界后的卖出加一次 3 倍替代买入；以及一次换手限制。
